# Глоссарий — RZD APPS

> Предметная область и внутренние сущности FSM. Термины отсортированы по смысловым группам.

## Предметная область (завод)

| Термин | Значение |
|--------|----------|
| **РШР** | Рельсошпальная решётка — рельсовый отрезок ~25 м со шпалами и скреплением. Основная единица учёта. |
| **Число шпал (`sleepers`)** | Количество шпал на РШР = `ceil(гайки / 4)`. Норма ~50. **Это то, что реально считает система.** ⚠️ В UI колонка исторически подписана «Эпюра», хотя показывает именно число шпал. |
| **Эпюра** | Раскладка шпал — **расстояние между шпалами** (нормативно задаётся как число шпал на километр пути). ⚠️ Это **НЕ** количество шпал на РШР. Термин часто путают; в этом проекте под «эпюрой» в UI/коде фактически подразумевается число шпал (`sleepers`) — историческая неточность именования. |
| **Шпала** | Поперечный элемент; на неё приходятся 4 гайки крепления. Один цикл закрутки = одна шпала. |
| **Забег** | Продольное несовпадение торцов левой и правой рельсовой нити в звене, мм. Знаковый: «+» — левая нить забежала вперёд. Считается отдельно в начале и в конце РШР. ⚠️ Это **НЕ** эпюра и **НЕ** длина: длину по тем же полям считать нельзя (см. [ADR-0010](adr/0010-overhang-from-edge-difference.md)). |
| **Скрепление** | Крепёж рельса к шпале; фиксируется 4 гайками. |
| **Гайки ЛН / ЛВ / ПН / ПВ** | Левая наружная, левая внутренняя, правая наружная, правая внутренняя. Соответствуют каналам M1–M4 Modbus. |
| **Пост 1** | Участок геометрического контроля. Sensor1 с `sensor_id=1`. |
| **Пост 2** | Участок закрутки гаек. Sensor1 `sensor_id=2` (лазер) + Sensor2 (Modbus, моменты). |
| **«—» (прочерк шпал)** | В UI: РШР ещё `IN_PROGRESS`, число шпал не досчитано. Показывать прочерк, не 0. (Колонка в UI называется «Эпюра».) |
| **Отбраковка** | РШР короче ~15 м или слишком долгий проезд поста 1 → не идёт в учёт. Бывает авто и ручная. |
| **Парковка между сменами** | Недокрученная РШР остаётся `IN_PROGRESS` на посту 2 в конце смены; продолжается после рестарта/утром. |

## Датчики и сигналы

| Термин | Значение |
|--------|----------|
| **Sensor1 (РШР-сканер)** | Геометрия, лазеры, `mmAlongRail`, износ, ширина колеи. `POST /sensor/first`. Оба поста шлют Sensor1, различаются `sensor_id`. |
| **Sensor2 (ПЛК / Modbus)** | Моменты закрутки M1–M4, частоты f1–f4, сопротивление R, температура T, влажность H. `POST /sensor/second`. |
| **mmAlongRail** | Позиция вдоль рельса по энкодеру (мм). Сбрасывается в ~0 на границе рельсов (каждые ~25 м). |
| **M1–M4 / `frequency_torque_1..4`** | Момент закрутки по 4 каналам (Нм). |
| **f1–f4 / `converter_frequency_1..4`** | Частота привода инструмента (Гц). |
| **R / T / H** | Сопротивление рельсовой цепи / температура / влажность. |
| **Цикл закрутки** | Один проход инструмента по 4 гайкам одной шпалы. Пауза между циклами ~7–8 с. |

## Внутренние сущности FSM (in-memory)

| Термин | Значение |
|--------|----------|
| **`SENSOR_STATE` / `SensorState`** | In-memory «истина» о конвейере. БД — только персистентность. |
| **`active` / `_active`** | РШР, которая сейчас на посту 1 (`RailSession`). |
| **`rail_at_post2`** | РШР, которая сейчас закручивается на посту 2. Единственный получатель гаек. |
| **`waiting_at_post2` / `_waiting_at_post2`** | Припаркованные сессии: сняты с `active`, ждут/идут закрутку. |
| **FIFO поста 2** | Очередь `rail_id`, ожидающих сегмента на посту 2 (`Post2Tracker.fifo_rail_ids`). |
| **`Post2Tracker`** | Состояние поста 2: FIFO, `rail_at_post2`, `rail_at_post2_max_mm`, pending segment. |
| **Парковка (`park`)** | Снятие с `active` в `waiting_at_post2` **без** финализации. Противоположность — `close`/`finalize`. |
| **Финализация (`finalize`)** | Закрытие РШР: статус `COMPLETED`, расчёт числа шпал, длины, ошибок. Только на уходе с поста 2. |
| **Settle-окно** | Короткая пауза (15 с) после чистого гашения лазера поста 2 — досчитать «хвост» закрутки перед финализацией. |
| **Grace-фолбэк** | Долгое окно (120 с) закрытия, если чистого OFF лазера не было (разреженные данные). |
| **Watermark (per-stream)** | Отметка времени последнего обработанного пакета по каждому потоку (`s1:1`, `s1:2`, `s2`) для детекции опоздавших. |
| **`merged_queue`** | Единая очередь событий S1+S2, сортировка по времени с буфером `REORDER_BUFFER_MS`. |

## Статусы и события

| Термин | Значение |
|--------|----------|
| **`IN_PROGRESS`** | РШР открыта, не финализирована. Число шпал ещё не посчитано. |
| **`COMPLETED`** | РШР финализирована (число шпал, длина, ошибки записаны). |
| **Pipeline-события** | Диагностическая цепочка: `rshr_opened`, `rshr_parked_post1`, `post2_recognized`, `tightening_started`, `tightening_completed`, `rshr_departed_post2`, `rshr_closed`, `modbus_skipped`, `packet_stale`, `rshr_discarded`, `worker_error`. |
| **Stream Monitor** | Диагностический буфер событий (`/monitor`, без auth). Не влияет на FSM. |

## Инфраструктура

| Термин | Значение |
|--------|----------|
| **tochnost** | Backend (FastAPI, Python), ветка `dev`, порт 8000. |
| **rzd** | Frontend (React 19 + FSD, TS), ветка `main`, порт 3003 (nginx). |
| **rshr_core** | Общая логика закрутки/таймингов/длины; используется в backend и офлайн-симуляторе. |
| **TimescaleDB** | Хранилище истории (расширение PostgreSQL для временных рядов). |
| **FSD** | Feature-Sliced Design — архитектура фронтенда (`app/pages/widgets/features/entities/shared`). |
| **Telegram burst** | 20 фото/сек с камеры при уходе РШР с поста 2. |
