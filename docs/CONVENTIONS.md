# CONVENTIONS — код, git, рабочий процесс

> Правила для агентов и людей. Инварианты поведения — [SPEC.md §6](../SPEC.md).

## 1. Два репозитория — коммитить раздельно

| Папка | Репо | Ветка деплоя | Порт |
|-------|------|--------------|------|
| `tochnost/` | backend (FastAPI, Python) | `dev` | 8000 |
| `rzd/` | frontend (React + FSD, TS) | `main` | 3003 |

- Корень `RZD APPS/` — **рабочая папка, не git-репо**. Harness-файлы в корне канонические; их копии лежат в каждом репо.
- **Никогда не коммить кросс-репо одним заходом.** `cd tochnost && git ...`, отдельно `cd rzd && git ...`.
- Коммитить/пушить **только по явной просьбе** пользователя.
- **Не коммить `.env`** с секретами. Не коммить `.venv/`, `node_modules/`, `*.tsbuildinfo`.

## 2. Стиль кода

**Backend (Python, `tochnost/`)**
- Python 3.12, `uv` для зависимостей (`pyproject.toml`, `uv.lock`).
- Тайминги/пороги — **только** через `RshrTimingConfig` (ENV-backed), не хардкодить магические числа в `service.py`.
- FSM-логика централизована в `sensor/service.py` + `state.py`; переиспользуемое (циклы, длина) — в `rshr_core/`.
- Комментарии — по делу, на русском, объясняют «почему» (как в существующем `config.py`).

**Frontend (TS, `rzd/`)**
- FSD-слои, импорт только вниз: `app → pages → widgets → features → entities → shared`. Не импортировать «вверх» или «вбок» между фичами.
- `pnpm` (есть `pnpm-lock.yaml`), Vite + `@vitejs/plugin-react-swc`.
- Перед сдачей: `pnpm typecheck && pnpm lint`. Форматирование — Prettier (`pnpm format`).
- Тяжёлое (Three.js 3D-модель) — `lazy`, code splitting сохранять.

## 3. Терминология (важно)

- **Число шпал** (`sleepers` = `ceil(гайки/4)`) — то, что считает система. Норма ~50.
- **Эпюра** — расстояние между шпалами (раскладка). ⚠️ **Не** количество шпал. UI-колонка называется «Эпюра», но показывает число шпал — историческое имя, новый текст пишем как «число шпал».
- Гайки: **ЛН/ЛВ/ПН/ПВ** = каналы M1–M4.

## 4. Работа с FSM — правила безопасности

1. Перед правкой FSM/закрутки — прочитать [SPEC.md](../SPEC.md) и релевантный [ADR](adr/). Инварианты не «упрощать».
2. После правки — прогнать офлайн-реплей ([TESTING.md](TESTING.md)), сверить эталон (13 РШР / 1164 гайки).
3. Менял поведение — обнови SPEC (FR/INV/пороги) и ADR в том же изменении.
4. Не `close_active_rail` на посту 1 (только `park`); гайки только на `rail_at_post2`; per-stream watermark; на проде `VITE_API_BASE_URL` пустой. См. INV-1…8.

## 5. Планы задач

- Планы живут в [docs/plans/](plans/) (`*.plan.md`). Перед работой — свериться с актуальным статусом в git (план мог быть частично выполнен).
- Крупную задачу оформлять планом до реализации.

## 6. Definition of Done (для изменения поведения)

- [ ] Код + тест/реплей зелёные, эталон сходится.
- [ ] Инварианты не нарушены.
- [ ] SPEC/ADR/RUNBOOK обновлены при изменении контракта или порогов.
- [ ] Harness-копии синхронизированы, если правился общий док (`scripts/sync-harness.sh`).
- [ ] Секреты не в коммите.

## 7. Коммиты

- Осмысленный scope-префикс (`feat(queue)`, `fix(fsm)`, `docs(harness)`).
- Один логический сдвиг — один коммит; не мешать backend и frontend.
