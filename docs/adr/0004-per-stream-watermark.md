# ADR-0004. Per-stream watermark, не общий

**Статус:** принято · **Инвариант:** INV-4

## Контекст
Для защиты от out-of-order пакетов FSM держит watermark (время последнего обработанного пакета). При **общем** watermark на все потоки: Modbus (Sensor2) опережал РШР-сканер (Sensor1) на ~11 с (дрейф часов ПЛК/сканера) → более «свежий» Modbus поднимал watermark, и все пакеты Sensor1 помечались `packet_stale` и отбрасывались. Геометрия переставала писаться.

## Решение
Watermark **раздельный по потокам**: `s1:1` (пост 1), `s1:2` (пост 2), `s2` (Modbus). Опоздание считается внутри своего потока. Дополнительно `drop_stale_by_received_at=False` по умолчанию — не отбрасывать по абсолютному возрасту (дрейф часов не должен глушить поток).

## Последствия
- Sensor1 и Sensor2 не глушат друг друга при рассинхроне часов.
- NTP на объекте всё равно обязателен (хронология `merged_queue`).

## Отвергнутые альтернативы
- *Один watermark* — исходный баг.
- *Дроп по received_at* — при дрейфе ПЛК глушит весь поток.

## Где в коде
`tochnost/src/rshr_core/late_packets.py`, `config.py: drop_stale_by_received_at`. FAQ-6 онбординга. Коммит `8862625`.
