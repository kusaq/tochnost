# ADR-0002. Гайки пишутся на `rail_at_post2`, не на `active`

**Статус:** принято · **Инвариант:** INV-2

## Контекст
Штатный режим — параллельный: пока на посту 2 закручивается РШР A, на посту 1 уже едет РШР B (`active = B`). Modbus (моменты) физически относится к A. Раньше гайки писались на `get_active_rail()` (= B) → на новую РШР B «налипало» ~70 чужих гаек, а A недосчитывала.

## Решение
Получатель гаек определяется **только** через `_modbus_target_rail_id()` = `rail_at_post2`. Если `rail_at_post2 is None` → событие `modbus_skipped` (штатно при пустых постах). `active` (пост 1) гайки не получает никогда.

## Последствия
- Гайки всегда на той РШР, которая физически на посту 2.
- `modbus_skipped` при активной закрутке (лазер post2 ON) — это **баг** (проверять FIFO/`post2_recognized`), при пустых постах — норма.

## Отвергнутые альтернативы
- *Привязка по времени к последней открытой* — ломается в параллельном режиме.

## Где в коде
`tochnost/src/api/v1/sensor/service.py`: `_modbus_target_rail_id`, `add_screw`, `add_sensor2_data`. FAQ-4 онбординга.
