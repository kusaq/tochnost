# ADR-0005. Детекция старта/конца цикла закрутки

**Статус:** принято · **Инвариант:** INV-5

## Контекст
Одна шпала = один цикл = 4 гайки. ПЛК отдаёт пики моментов M1–M4 раз в ~1 с, иногда все 4 пика приходят одним пакетом с точностью до секунды. Наивная детекция («есть момент → старт, нет момента → конец») давала **два цикла на одну шпалу**: FSM закрывал цикл после провала сигнала и тут же открывал новый на том же проходе. Также ложные старты по одной лишь частоте привода без момента.

## Решение
- **Старт цикла:** `has_moment_activity(M1..M4 > 0)` **И** пауза от прошлого цикла ≥ `MIN_INTER_CYCLE_SEC` (7 с). Только по моментам, не по частоте.
- **Конец цикла:** `all_torque_zero()` подряд `CYCLE_END_ZERO_PACKETS` раз (онлайн 2, чтобы не рвать на кратком провале; офлайн 1 на упорядоченных данных).
- Повторная закрутка той же шпалы в пределах `MIN_SLEEPER_SPACING_MM` (250 мм) обновляет гайки, а не плодит дубль.

## Последствия
- Один проход инструмента = один цикл = 4 гайки.
- Онлайн и офлайн пресеты (`CYCLE_END_ZERO_PACKETS` 2 vs 1) настроены сходиться на реальных данных.

## Отвергнутые альтернативы
- *Старт по частоте* — ложные циклы.
- *Конец по 1 нулевому пакету онлайн* — рвёт цикл на джиттере.

## Где в коде
`tochnost/src/rshr_core/tightening.py` (`has_moment_activity`, `all_torque_zero`, `detect_cycles_in_window`), `config.py`, `service.py: _finalize_tightening_cycle`. FAQ-5 онбординга.
