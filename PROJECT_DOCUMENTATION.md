# Документация проекта: Система сбора данных для рельсошпальных решеток

## Общее описание

Проект представляет собой FastAPI-приложение для автоматизированного сбора данных с промышленных датчиков и камер при прохождении рельсошпальных решеток по конвейеру. Система объединяет:

- **Modbus-контроллер** для считывания показаний датчиков (4 гайковёрта + сопротивление)
- **Камеры Hikvision** для захвата изображений (вид сверху и спереди)
- **PostgreSQL** для хранения всех собранных данных
- **Автоматическое обнаружение движения** решеток по конвейеру

Каждая решетка получает уникальный UUID, и для неё собирается полный набор данных: показания датчиков Modbus (каждую секунду во время движения) и серия фотографий с камер.

## Основные компоненты

### 1. **app/main.py** — FastAPI приложение

Главный файл приложения, определяющий все API эндпоинты и жизненный цикл приложения.

#### Эндпоинты:

**Авторизация:**
- `POST /auth/token` — получение JWT токена (логин/пароль из `.env`)

**Система:**
- `GET /health` — проверка работоспособности (без авторизации)

**Камеры:**
- `POST /api/v1/capture` — запуск захвата изображений с камер
- `POST /api/v1/cameras/test` — проверка доступности камер

**Modbus:**
- `POST /api/v1/modbus/readings` — ручное одноразовое чтение Modbus
- `GET /api/v1/modbus/poll/status` — статус автоматического опроса
- `POST /api/v1/modbus/poll/start` — запуск автоматического опроса
- `POST /api/v1/modbus/poll/stop` — остановка автоматического опроса

**Решетки:**
- `GET /api/v1/rail-grids` — список всех решеток
- `GET /api/v1/rail-grids/{grid_uuid}` — информация о конкретной решетке

#### Жизненный цикл:

- **При старте** (`on_startup`): создание таблиц БД, запуск фонового опроса Modbus (если включено)
- **При остановке** (`on_shutdown`): корректное завершение опроса Modbus, завершение активной решетки

#### Логирование:

Все эндпоинты логируют свои действия с префиксом `[API]`, включая ошибки с подробными сообщениями.

### 2. **app/config.py** — Конфигурация

Использует `pydantic-settings` для загрузки всех настроек из `.env` файла.

#### Основные группы настроек:

**API:**
- `API_TITLE`, `API_VERSION` — метаданные API

- `API_USERNAME`, `API_PASSWORD` / `API_PASSWORD_HASH` — авторизация

- `MODBUS_POLL_INTERVAL_SEC` — интервал опроса во время активного сбора (по умолчанию 1 сек)
- `MODBUS_DETECTION_INTERVAL_SEC` — интервал опроса для обнаружения движения (по умолчанию 15 сек)
- `MODBUS_POLL_ENABLED` — включить автоматический опрос при старте

**Hikvision камеры:**
- `HIKVISION_USER`, `HIKVISION_PASS` — учётные данные
- `HIKVISION_TOP_IP`, `HIKVISION_FRONT_IP` — IP адреса камер
- `HIKVISION_TOP_CHANNEL`, `HIKVISION_FRONT_CHANNEL` — номера каналов
- `HIKVISION_RTSP_PORT` — порт RTSP
- `HIKVISION_CAPTURE_INTERVAL` — интервал захвата кадров (секунды)
- `HIKVISION_CAPTURE_DURATION_MIN` — длительность захвата (минуты)
- `HIKVISION_PREVIEW` — показывать превью
- `HIKVISION_CROP_TOP/BOTTOM/LEFT/RIGHT` — обрезка изображений
- `HIKVISION_JPEG_QUALITY` — качество JPEG (10-100)
- `HIKVISION_ARCHIVE_AFTER_CAPTURE` — создавать архив после захвата
- `HIKVISION_ARCHIVE_REMOVE_ORIGINALS` — удалять оригиналы после архивации

**Данные:**
- `DATA_ROOT` — корневая директория для сохранения изображений

#### Функция `get_settings()`:

Использует `@lru_cache` для кэширования экземпляра настроек, чтобы не перечитывать `.env` каждый раз.

### 3. **app/models.py** — Модели базы данных

SQLAlchemy ORM модели для трёх основных сущностей:

#### **RailGrid** (рельсошпальная решетка)

Основная сущность, представляющая одну решетку, проходящую по конвейеру.

**Поля:**
- `id` — первичный ключ
- `uuid` — уникальный идентификатор (UUID4, индекс)
- `connection_class` — класс соединения (опционально)
- `status` — статус: `"active"` (в процессе) или `"completed"` (завершена)
- `started_at` — время начала движения
- `completed_at` — время завершения (опционально)
- `extra` — дополнительные данные (JSON)

**Связи:**
- `modbus_readings` — все показания Modbus для этой решетки (один-ко-многим)
- `capture_sessions` — все сессии фотографирования для этой решетки (один-ко-многим)

#### **ModbusReading** (показание Modbus)

Одно показание всех датчиков Modbus в определённый момент времени.

**Поля:**
- `id` — первичный ключ
- `timestamp` — время считывания
- `values` — список значений датчиков (JSON)
- `extra` — метаданные (источник, переменные и т.д.)
- `rail_grid_id` — внешний ключ на `RailGrid` (опционально, для привязки к решетке)

**Связи:**
- `rail_grid` — решетка, к которой относится это показание

#### **CaptureSession** (сессия фотографирования)

Результат одного запуска захвата изображений с камер.

**Поля:**
- `id` — первичный ключ
- `uid` — идентификатор элемента (обычно UUID решетки)
- `connection_class` — класс соединения
- `front_saved`, `top_saved` — количество сохранённых изображений
- `front_dir`, `top_dir` — пути к директориям с изображениями
- `front_archive`, `top_archive` — пути к архивам (если созданы)
- `errors` — список ошибок (JSON)
- `camera_config` — конфигурация камер при захвате (JSON)
- `created_at` — время создания записи
- `rail_grid_id` — внешний ключ на `RailGrid` (опционально)

**Связи:**
- `rail_grid` — решетка, для которой выполнялся захват

### 4. **app/services/modbus_poller.py** — Фоновый опрос Modbus и обнаружение решеток

**Ключевой компонент системы** — автоматически обнаруживает движение решеток и собирает данные.

#### Логика работы:

**1. Режим обнаружения (Detection Mode):**
- Опрашивает Modbus каждые **15 секунд** (настраивается через `MODBUS_DETECTION_INTERVAL_SEC`)
- Собирает **3 образца** базовых значений, когда конвейер стоит без движения
- Сравнивает новые значения с базовыми
- Если значения отличаются больше чем на **0.1** (порог стабильности) — начинается движение решетки

**2. Режим активного сбора (Active Collection Mode):**
- Опрашивает Modbus **каждую секунду** (настраивается через `MODBUS_POLL_INTERVAL_SEC`)
- Создаёт новую запись `RailGrid` с UUID
- Сохраняет все показания Modbus в `ModbusReading` с привязкой к решетке
- **Автоматически запускает захват изображений** с камер через `camera_service`
- Отслеживает стабильность значений: если **5 подряд** показаний одинаковы (в пределах порога) — решетка завершена

**3. Завершение решетки:**
- Обновляет статус `RailGrid` на `"completed"`
- Устанавливает `completed_at`
- Возвращается в режим обнаружения

#### Методы класса `ModbusPoller`:

- `start()` — запуск фонового опроса
- `stop()` — остановка опроса (корректно завершает активную решетку)
- `is_running()` — проверка статуса
- `get_status()` — получение детального статуса (режим, текущая решетка, базовые значения и т.д.)

#### Внутренние методы:

- `_establish_baseline()` — установка базовых значений (когда конвейер стоит)
- `_poll_for_detection()` — опрос в режиме обнаружения
- `_poll_active_collection()` — опрос в режиме активного сбора
- `_start_rail_grid()` — создание новой решетки и запуск камер
- `_complete_rail_grid()` — завершение решетки
- `_extract_numeric_values()` — извлечение числовых значений из показаний
- `_values_differ()` — проверка, отличаются ли значения от базовых
- `_all_values_similar()` — проверка стабильности значений
- `_start_camera_capture()` — запуск захвата изображений (асинхронно, в отдельном потоке)

#### Логирование:

Все действия логируются с префиксом `[POLLER]`, включая:
- Переключение режимов
- Установку базовых значений
- Обнаружение движения
- Создание/завершение решеток
- Ошибки подключения к Modbus
- Ошибки сохранения в БД

### 5. **app/services/modbus_service.py** — Прямое чтение Modbus

Низкоуровневая функция для чтения значений из Modbus устройства.

#### Функция `read_modbus()`:

**Параметры:**
- `settings` — настройки приложения
- `variables` — список переменных для чтения (если `None`, используются значения по умолчанию)

**Значения по умолчанию:**
- `wrench_1`, `wrench_2`, `wrench_3`, `wrench_4` — адреса 1-4, тип `int`
- `resistance` — адрес 5, 2 регистра, тип `float_swapped` (байты переставлены)

**Возвращает:**
- Список `ModbusValue` с именем, адресом, сырыми регистрами и декодированным значением

**Обработка ошибок:**
- Подключение к Modbus устройству
- Чтение регистров
- Декодирование значений
- Подробное логирование с префиксом `[MODBUS]` и советами по устранению неполадок

### 6. **app/services/camera_service.py** — Работа с камерами Hikvision

Сервис для захвата изображений с камер Hikvision через RTSP.

#### Функция `capture_with_cameras()`:

**Параметры:**
- `request: CaptureRequest` — параметры захвата (UID, количество кадров, интервалы, настройки камер)
- `settings: Settings` — настройки приложения (используются как значения по умолчанию)

**Логика:**
1. Разрешение URL камер (из запроса или из настроек)
2. Создание `DataCollector` из `collect_data.py` с параметрами:
   - `show_preview`, `crop_*`, `jpeg_quality`, `archive_*` — берутся из запроса, если указаны, иначе из `settings`
3. Запуск захвата изображений
4. Возврат результата (`CaptureResponse`) с количеством сохранённых изображений, путями и ошибками

#### Функция `test_cameras()`:

Проверяет доступность камер по URL (RTSP или HTTP).

**Возвращает:**
- Список `CameraTestResult` с информацией о доступности каждой камеры

#### Логирование:

Все действия логируются с префиксом `[CAMERA]`, включая:
- Разрешение URL камер
- Инициализацию `DataCollector`
- Процесс захвата
- Ошибки подключения и захвата

## Рабочий процесс системы

### Типичный сценарий работы:

1. **Запуск приложения:**
   - Создаются таблицы БД (если их нет)
   - Запускается `ModbusPoller` в режиме обнаружения (опрос каждые 15 сек)

2. **Установка базовых значений:**
   - Пока конвейер стоит, poller собирает 3 образца показаний Modbus
   - Эти значения становятся "базовыми" (baseline)

3. **Обнаружение движения решетки:**
   - При опросе Modbus значения отличаются от базовых
   - Создаётся новая запись `RailGrid` с UUID
   - Poller переключается в режим активного сбора (опрос каждую секунду)
   - Автоматически запускается захват изображений с камер

4. **Активный сбор данных:**
   - Каждую секунду считываются показания Modbus и сохраняются в БД с привязкой к решетке
   - Камеры продолжают захватывать изображения с заданным интервалом

5. **Завершение решетки:**
   - Когда 5 подряд показаний Modbus стабильны (одинаковы) — решетка считается завершённой
   - Обновляется статус `RailGrid` на `"completed"`, устанавливается `completed_at`
   - Poller возвращается в режим обнаружения

6. **Результат:**
   - В БД есть полная запись о решетке с UUID
   - Все показания Modbus за время прохождения (каждую секунду)
   - Сессия фотографирования с путями к изображениям и архивам

## Конфигурация и переменные окружения

Все настройки приложения хранятся в файле `.env` (который **не игнорируется** в git для удобства разработки).

### Структура `.env`:

Файл разделён на секции:
- **API Settings** — настройки API и авторизации
- **Database** — подключение к PostgreSQL
- **Modbus Settings** — параметры Modbus контроллера
- **Hikvision Camera Settings** — настройки камер
- **Data Storage** — пути для сохранения данных

### Важные моменты:

- **Булевы значения** должны быть `true`/`false` (не `0`/`1` или `True`/`False`)
- **Все переменные опциональны** — есть значения по умолчанию в `config.py`
- **Шаблон** находится в `env.sample` — можно скопировать и заполнить

Подробная инструкция по настройке — в файле `ENV_SETUP.md`.

## Логирование

Все сервисы и контроллеры используют подробное логирование с префиксами:

- `[API]` — действия в API эндпоинтах
- `[POLLER]` — действия в Modbus poller
- `[MODBUS]` — действия при чтении Modbus
- `[CAMERA]` — действия при работе с камерами

### Уровни логирования:

- **INFO** — нормальные операции (запуск/остановка, создание решеток, успешные чтения)
- **WARNING** — предупреждения (ошибки сохранения в БД, недоступные камеры)
- **ERROR** — ошибки (неудачное подключение, исключения)
- **DEBUG** — детальная отладочная информация

### Формат:

Логи выводятся в консоль (stdout) в формате, определённом Python logging.

## Обработка ошибок

### В API эндпоинтах:

- **400 Bad Request** — ошибки конфигурации (неверные параметры запроса)
- **401 Unauthorized** — ошибки авторизации
- **404 Not Found** — ресурс не найден (например, решетка по UUID)
- **503 Service Unavailable** — недоступность внешних устройств (Modbus, камеры)
- **500 Internal Server Error** — неожиданные ошибки

Все ошибки логируются с подробными сообщениями и контекстом.

### В сервисах:

- **RuntimeError** — ошибки подключения к внешним устройствам
- **ValueError** — ошибки конфигурации
- **Exception** — общие исключения с подробным логированием

## Важные замечания для разработчиков

### 1. **Файл `.env` не игнорируется**

В отличие от стандартной практики, `.env` файл **не игнорируется** в git (но игнорируются `.env.local`, `.env.*.local`). Это сделано для удобства разработки. В production следует использовать переменные окружения системы или секреты.

### 2. **Автоматический запуск камер**

При обнаружении движения решетки камеры запускаются **автоматически** через `_start_camera_capture()` в `modbus_poller.py`. Это происходит асинхронно в отдельном потоке, чтобы не блокировать опрос Modbus.

### 3. **Базовые значения (baseline)**

Базовые значения устанавливаются автоматически при первом запуске poller. Если конвейер уже движется при старте, система может неправильно определить базовые значения. Рекомендуется запускать приложение, когда конвейер стоит.

### 4. **Пороги стабильности**

Порог для определения "отличия" значений и "стабильности" (для завершения решетки) установлен в **0.1**. Это значение можно настроить в коде `modbus_poller.py` (переменная `_stability_threshold`).

### 5. **Интервалы опроса**

- **15 секунд** — для обнаружения движения (можно настроить через `MODBUS_DETECTION_INTERVAL_SEC`)
- **1 секунда** — для активного сбора данных (можно настроить через `MODBUS_POLL_INTERVAL_SEC`)

### 6. **Тесты используют реальный `.env`**

Тесты загружают настройки из `.env` через `get_settings()`, поэтому перед запуском тестов убедитесь, что `.env` настроен корректно (или используйте моки для настроек).
